# 前端工程规范

## Vue / JavaScript 业务注释

修改`<script>`或函数时，按annotation.md执行函数全覆盖审查。适用段落包括：
1. 请求参数来源（表单、路由、缓存或登录上下文）
2. 筛选条件代表的业务范围
3. 返回数据写入哪个表格、弹窗或页面状态
4. 字典转换后的展示用途
5. 校验规则防止的业务错误
6. 权限分支影响的按钮、字段或金额
7. 多请求串行等待或并行的原因
8. 分页、排序、查询是否使用同一数据源

模板中简单绑定不强制注释；复杂权限表达式和不直观事件链应说明业务场景。

## 组件选型

- 简单表单：`el-form` + `el-form-item`
- 复杂表格（编辑/筛选/导出）：`vxe-table`
- 简单展示列表：`el-table`
- 弹窗编辑：`el-dialog` + `el-form`
- 树形选择：项目已有树选择组件

遵循现有Vue 2 / Element UI技术栈，不因局部修改迁移框架。

详细设计模式与组件化决策参见 design-principles.md。

## 组件抽取标准

### 必须抽取为独立 .vue 组件

| 场景 | 理由 |
|---|---|
| 弹窗/抽屉（el-dialog / el-drawer） | 主页面职责分离，弹窗逻辑独立可测试 |
| 复杂表单（>10 个字段或含嵌套/联动逻辑） | 表单逻辑复杂时独立组件更易维护 |
| 可复用业务区块（在 2 个以上页面出现） | 避免代码重复，统一维护 |
| 选项卡内的独立业务面板 | 面板逻辑独立，不污染父组件 |

### 允许保留在主页面

| 场景 | 理由 |
|---|---|
| 简单查询条件（<5 个字段，无联动） | 不值得抽组件 |
| 页面级独有逻辑且无法复用 | 抽组件增加间接层但无收益 |
| 历史代码修复，抽组件会扩大影响范围 | 最小侵入优先，参见 design-principles.md 决策矩阵 |

### 组件通信规范

```text
父 → 子：props（数据下沉）
子 → 父：$emit（事件上报）
弹窗数据：props 传入初始数据，$emit 返回结果
```

### 组件文件组织

```text
views/模块名/
  ├── 页面名.vue              # 主页面
  ├── components/             # 页面级组件
  │   ├── XxxDialog.vue       # 弹窗组件
  │   ├── XxxForm.vue         # 复杂表单组件
  │   └── XxxDetail.vue       # 详情面板组件
  └── mixins/                 # 页面级混入（可选）
```

## 响应式与状态

- Vue 2数组索引和动态属性使用`this.$set`
- 弹窗关闭时清理表单值和校验状态
- 表格刷新后评估选中状态是否应清除
- `vxe-table`配置稳定、唯一的`row-id`
- 查询/重置/分页/排序调用同一数据接口，保持总数口径一致
- 无依赖请求优先并行；有依赖时注释等待原因

## 设计系统

- 主框架：Element UI 2.15；微前端按现有Element Plus版本
- 颜色与字号：使用设计变量，禁止硬编码
- 间距：4px倍数（4/8/12/16/24/32）
- z-index：弹窗2000+、tooltip3000+
- 样式：scoped，避免全局污染
- 类名：自定义用业务前缀，不覆盖组件库内置类

## CSS合并

同一文件、同一作用域中的重复选择器必须合并（不同@media断点和明确级联覆盖除外）。

- `!important`高于普通声明
- 同优先级以后出现的为准
- 选择器按作用范围从大到小排列

纯CSS变更不要求业务注释，但必须检查同名class和作用域。

## 布局决策

### DOM 结构优先于 CSS 补丁

修改布局问题时，按以下顺序评估方案——优先调整结构，最后才用 CSS 数学计算布局：

1. **调整容器结构**（新增 wrapper、分组、区域隔离）— 优先
2. **使用流式布局**（flex-wrap、grid auto-fill）— 其次
3. **CSS 数学计算**（calc、百分比、flex-basis）— 最后手段
4. **禁止** `overflow: hidden` 隐藏业务可见内容（输入框、按钮、表格列）

### 布局修复不受「原位最小修改」约束（升级阶梯）

布局/样式问题的根因常在 DOM 结构，此时调整 DOM 本身就是最小修改；死守"只改 CSS 值"只会把补丁越堆越厚（口径见 `CLAUDE.md` §二）。修复时按以下阶梯逐级上升，**禁止在同一级反复硬改**：

```text
改 CSS 值 → 改 CSS 结构（flex/grid）→ 调整 DOM 结构 → 重组容器
```

**止损条件**：同一级连续尝试 **2 次**仍不生效，立即停止并升到上一级，同时说明本级为何治不好（根因落在哪一层）。绝不为压住症状在同一层级轮番叠加 `margin` / `padding` / `!important` / `overflow`。

### 决策矩阵

| 空间不足表现 | 禁止方案 | 正确方案 |
|---|---|---|
| 查询字段被挤出视口 | `overflow: hidden`、强制 `flex-wrap: nowrap` | `flex-wrap: wrap` + 每项设 `min-width`，允许自然换行 |
| 表格高度不随查询区变化 | 表格写死 `height: calc(100vh - Npx)` | 父容器 `flex column`，表格 `flex: 1` 自适应剩余空间 |
| 多个输入框单行放不下 | 缩小每项宽度硬塞到一行 | 新增容器分组（如按业务逻辑分为两行），允许自然换行 |
| 弹窗表单字段溢出 | 水平滚动条 | 分列布局（2 列 / 3 列 grid）或分步表单 |
| 按钮组与输入框抢空间 | 按钮被挤出或重叠 | 按钮组 `flex-shrink: 0` + `margin-left: auto` 固定在右侧 |

### 查询区 + 表格区标准布局模式

LIMS 系统最常见的页面结构是"查询条件 + 数据表格"。标准布局要求：

```text
父容器 (flex-direction: column, height: 100%)
  ├── 查询区 (flex-wrap: wrap, 高度由内容撑开，不设固定高度)
  │     ├── 表单项 (min-width: 200px~240px, flex: 1，允许换行)
  │     └── 按钮组 (flex-shrink: 0, 不参与宽度均分)
  └── 表格区 (flex: 1, overflow: auto, 占据剩余全部空间)
```

关键约束：
- 查询区高度**由内容决定**，换行后自动增高
- 表格区**占据剩余空间**，查询区增高时表格自动变矮
- 绝不允许查询区和表格区在同一层平铺后用绝对定位或固定高度拼凑

### 表单编辑区布局原则

- 表单项超过 4 个时，采用多列 grid 或 flex-wrap 布局
- 必填项与非必填项在同一行时，视觉权重一致（不靠缩进区分）
- 表单底部操作按钮区与表单内容区用独立容器隔离，不共享 flex 上下文

## 浏览器验证

> **工具选择以项目 CLAUDE.md §五 为硬规则**。下方仅描述验证流程。

可在浏览器观察的前端变更必须：
1. **连接已有服务**：用 `mcp__chrome-devtools__list_pages` 检查浏览器现有页面；若用户已声明服务已启动，直接提供 URL 或选择现有页面，**禁止重复执行启动命令**
2. 检查控制台错误和失败请求
3. 验证页面文本、结构和交互
4. CSS 使用 `mcp__chrome-devtools__take_snapshot` + `mcp__chrome-devtools__evaluate_script` 确认精确样式
5. 涉及布局时用 `mcp__chrome-devtools__resize_page` 检查适用尺寸
6. 提供截图、网络响应或日志作为证据

无法预览时说明原因和待视觉确认项，不得声称已完成。

### 预览调试工具选择

**以项目 CLAUDE.md §五 为准**。核心规则：
- 一律使用 `mcp__chrome-devtools__` 系列工具
- 禁止使用 `mcp__Claude_Browser__preview_*`（除非用户明确要求）
- 服务已运行时直接连接，不重复启动

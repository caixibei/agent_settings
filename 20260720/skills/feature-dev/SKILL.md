# 新增功能工作流

## 核心流程

```text
需求理解 → 表/接口/权限/状态影响分析 → 设计模式评估
→ 接口设计 → Service 业务实现 → Mapper/SQL → 前端 → 注释复查 → 测试
```

---

## 各阶段要点

### 需求理解
- 需求有歧义时一次确认一个关键问题
- 不猜测业务意图，不确定时标记 TODO
- **涉及角色差异、金额计算、状态流转时，按 `business-assumptions.md` 执行业务假设门控**

### 影响分析
- 表结构变更需同步：迁移脚本 → Entity → DTO → Mapper → Service → 前端
- 权限变更需确认：角色范围、数据范围、操作权限
- 状态变更需确认：状态机、流转规则、历史数据兼容

### 设计模式评估

> 详细决策矩阵见 `design-principles.md`。

新增功能**优先采用设计模式**，以下场景必须评估：

| 业务场景 | 推荐模式 |
|----------|----------|
| 多种业务类型走不同逻辑 | 策略模式 + Spring 注入 |
| 操作完成后多步副作用 | 观察者/事件（Spring Event） |
| 复杂查询条件构造 | 建造者模式 / QueryWrapper |
| 流程步骤相同但部分实现不同 | 模板方法 |
| 树形结构递归处理 | 组合模式 |

**禁止**：为用模式而用模式。当前只有一种实现且短期不扩展时，简单 if/else 即可。

### 接口设计
- 新增独立能力严格按 Controller → Service → Mapper 分层
- 跨模块访问使用目标模块 Service
- 复用已有接口前确认数据口径一致

### 前端实现

> 详细组件化标准见 `frontend.md`。
> **布局修改必须遵循 `frontend.md`「DOM 结构优先于 CSS 补丁」规则**：先读 DOM 结构，按升级阶梯选方案（结构 > 流式 > CSS），禁止盲改 CSS。

- **必须抽取为独立 .vue 组件**：弹窗/抽屉、复杂表单（>10 字段）、可复用业务区块
- **允许保留在主页面**：简单查询条件（<5 字段）、页面级独有逻辑
- **组件通信**：父→子 props，子→父 `$emit`，跨层级 EventBus/Vuex
- 弹窗关闭时清理表单值和校验状态（`destroy-on-close` 或 `resetFields()`）

### 后端实现
- 新增代码严格分层
- 按 `annotation.md` 标准添加业务注释
- 事务边界与完整业务操作一致，避免半成功状态

### 测试
- **正向流程**：核心功能正常走通
- **边界场景**：空值、极端值、并发
- **异常场景**：权限不足、状态不允许、数据不存在
- **前端验证**：使用 Chrome DevTools MCP 工具在浏览器中验证（见 CLAUDE.md §五）
- **布局验证**：按 `frontend.md` 升级阶梯检查，禁止 `overflow: hidden` 隐藏业务内容

---

## 常见陷阱

- 需求理解不充分导致返工
- 遗漏权限、状态、字段的同步
- 复用接口时数据口径不一致
- 注释只覆盖新增代码，忽略同方法其他段落
- 新增功能未评估设计模式适用性

---

## 交付要求

- 需求实现说明
- 变更清单（文件 + 影响）
- 测试用例和结果
- 未处理风险
- 业务注释示例

# 代码审查维度

## 审查方法

1. **静态读代码**：用 Read 工具逐文件审查，不运行程序
2. **重点审查**变更文件及其直接调用链
3. 涉及前端展示时，用 Chrome DevTools MCP 工具辅助验证（见 CLAUDE.md §五）

---

## 审查顺序（按严重级别）

### CRITICAL（发现即停止审查，立即报告）

1. SQL 注入：用户输入直接拼接（必须用 `#{}`）
2. 越权访问：删除/状态/金额/权限变更前未校验当前用户权限
3. 敏感信息泄露：密码、密钥、token、连接串硬编码或写入日志
4. **业务假设未验证**：涉及角色差异、额度计算、状态流转的修改未向用户确认（见 `business-assumptions.md`）

### MAJOR（逐项记录，建议修复）

4. 业务语义与数据正确性：逻辑错误、状态流转异常
5. 事务与异常：`@Transactional` 缺少 `rollbackFor`、事务内长耗时操作
6. N+1 查询与性能：循环内 getById/list/selectOne、全量后内存分页
7. 注释覆盖完整性：见下方「注释审查」段落

### MINOR（记录，不阻断）

8. 命名与格式：变量命名不规范、缺少低风险注释
9. 历史分层：被无必要扩大的修改

## 注释审查

> 注释审查的完整标准见 `annotation.md`，检查清单见 `/annotation-check` skill。
> 本节仅列出审查要点的快速索引。

逐方法检查以下要点：

1. 业务入口和上下文（为什么存在）
2. 权限与角色范围
3. 每个数据库/外部调用（来源、目的、条件、结果用途、空结果处理、性能意图）
4. 查询结果去向
5. 关键分支和空结果
6. 批量映射与顺序/去重
7. 状态、金额和敏感字段
8. 排序、分页与响应口径

**禁止行为**：
- 注释仅复述代码动作（如"查询委托单""处理结果"）
- 一条宽泛注释覆盖多个查询和分支
- 注释与代码行为不一致

---

## 交付要求

- 按严重级别分类列出问题
- 每个问题说明：文件、行号、问题描述、建议修复
- CRITICAL 问题**立即停止审查并报告**
- MAJOR 问题建议修复
- MINOR 问题记录但不阻断

# 注释审查清单

> **触发时机**：每次 Edit/Write 修改业务代码前自动执行，与代码变更在同一次 Edit 中一起写入。
> **前置条件**：**必须先用 Read 工具读取目标文件**，再输出审查清单。禁止未读代码就输出清单。
> 详细标准见 annotation.md。

## A档（Java/MyBatis/SQL）

- [ ] **已读取目标文件**，理解业务上下文（Read 工具，非推测）
- [ ] 已查阅 `engineering-core.md` 与 `pitfalls.md`
- [ ] 已输出注释审查计划：方法列表 + 逻辑段落 + 当前覆盖 + 处理方式
- [ ] 已逐段审查每个受影响方法，而非只检查修改行
- [ ] 每个数据库调用均计划说明：数据来源、业务目的、查询条件、结果用途、空结果处理、性能意图
- [ ] 每个关键分支均计划说明：进入场景、业务影响、结果去向
- [ ] 已检查旧注释是否过时、失真或仅复述代码
- [ ] 已按"新增严格分层、历史最小修复"评估架构影响
- [ ] 已确认不因分层问题扩大历史代码重构范围

**审查计划格式**：

| 方法 | 逻辑段落 | 当前状态 | 处理方式 |
|---|---|---|---|
| `queryList` | 权限范围构造 | 缺失 | 新增角色与数据范围说明 |
| `queryList` | 委托单批量查询 | 不完整 | 补数据来源、条件和结果用途 |
| `queryList` | 空结果分支 | 缺失 | 补跳过原因和页面影响 |

## B档（Vue script/template）

- [ ] **已读取目标文件**，理解业务上下文（Read 工具，非推测）
- [ ] 已查阅 `frontend.md` 与 `pitfalls.md`
- [ ] 已列出受影响函数及交互逻辑段落
- [ ] 请求参数来源、返回用途、校验规则和权限分支均有注释计划
- [ ] 涉及 API 调用（axios/fetch/request）时，说明：数据来源、业务目的、查询条件、结果用途、空结果处理
- [ ] 涉及 Vuex/Pinia 状态变更时，说明：触发场景、状态去向、下游影响
- [ ] 已检查现有交互注释与实现一致
- [ ] 组件选型符合项目规范
- [ ] 未引入无关重构

## C档（CSS/Style）

- [ ] 已搜索同名 class 并评估影响

# Subagent 约束

## 基本规则

- 代码变更由主代理亲自执行，Explore只读搜索除外。
- 当前全局策略禁止 Subagent 执行代码或规则文件编辑；“派发代码任务时”的模板仅在未来有更高优先级指令明确放开该限制时适用。
- 当前只允许 Subagent 进行只读探索、定位或交叉审查，所有 Edit / Write 由主代理完成。
- Subagent不得执行任何git命令。
- 不重复主代理和Subagent的搜索工作。

## 派发代码任务时

Prompt必须包含：
1. 修改目标和业务语义
2. 允许修改的文件范围
3. annotation.md的全方法覆盖要求
4. 数据库调用注释标准
5. 历史代码最小修复、不强制分层重构
6. 禁止git
7. 要求返回验证证据

只写”遵循项目规范”不算完成规则传递。

## Subagent返回格式

涉及代码修改时报告（以下为**最低要求**，不替代 `annotation.md` 的全方法覆盖标准）：
- 修改的方法列表和每个方法的逻辑段落清单
- 每段注释状态（保留/更新/新增）
- 数据库调用注释按 `annotation.md` 6 要素覆盖
- 关键分支和空结果语义
- 是否发现历史分层问题及处理理由
- 实际执行的验证和结果

> 派发 Prompt 中已要求遵循 `annotation.md`，Subagent 的返回格式是汇报结构，
> `annotation.md` 的业务注释质量标准仍然对 Subagent 生效。

## 主代理复查

Subagent的总结不能代替代码复查。主代理必须：
1. 读取实际变更
2. 逐方法核对注释覆盖
3. 检查注释与代码一致
4. 检查数据库查询后续用途是否明确
5. 检查是否引入无关重构

## 不合格处置

- 注释不完整或仅复述代码：拒绝该部分变更并亲自修正
- 擅自扩大重构范围：停止并恢复到用户授权范围内
- 无法确认业务意图：标记待确认并询问用户

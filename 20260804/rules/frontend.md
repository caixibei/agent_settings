# 前端工程规范

> 决策优先级见 CLAUDE.md §二。注释标准见 annotation.md。

---

## 一、触发条件

以下任务触发本规范：

- 元素被遮挡 / 溢出
- 查询区放不下字段
- 表格区域异常
- 按钮挤压 / 重叠
- 响应式布局失效
- 页面布局调整
- 样式异常修复
- 弹窗布局调整

---

## 布局修改方法论（已迁出）

布局修改的流程内容（修改前强制分析、四级修改层级、典型场景方案对比、验证机制、修改完成报告模板）已迁入 `frontend-layout` 技能，按需加载。

**核心纪律（常驻）**：修改前端布局前必须先分析根因，禁止发现页面异常直接改 CSS。详细的分析步骤、修改层级、止损规则、验证机制见 `frontend-layout` 技能。

---

## 五、低代码平台特殊约束

低代码平台生成的页面（如本项目的 `style:after` 区域）：

- 容器定位系统（`position` / `inset` / `z-index`）由平台控制
- 应通过平台自定义区域用 `order` / `flex-basis` 调整内容排列
- **禁止**覆盖容器定位方式（会引发 scoped style 特异性冲突，陷入 `!important` 叠加）

---

## 八、Vue / JavaScript 业务注释

修改`<script>`或函数时，按annotation.md执行函数全覆盖审查。适用段落包括：
1. 请求参数来源（表单、路由、缓存或登录上下文）
2. 筛选条件代表的业务范围
3. 返回数据写入哪个表格、弹窗或页面状态
4. 字典转换后的展示用途
5. 校验规则防止的业务错误
6. 权限分支影响的按钮、字段或金额
7. 多请求串行等待或并行的原因
8. 分页、排序、查询是否使用同一数据源

模板中简单绑定不强制注释；复杂权限表达式和不直观事件链应说明业务场景。

## 九、组件选型

| 场景 | 推荐 | 说明 |
|------|------|------|
| 简单表单 | `el-form` + `el-form-item` | 内置校验、布局一致 |
| 复杂表格（编辑/筛选/导出） | `vxe-table` | 功能丰富，支持虚拟滚动 |
| 简单列表/展示 | `el-table` | 不过度引入 vxe-table |
| 弹窗编辑 | `el-dialog` + `el-form` | 统一交互模式 |
| 树形选择 | `el-tree-select` | 与后端接口格式一致 |

遵循现有Vue 2 / Element UI技术栈，不因局部修改迁移框架。

> 项目级 CLAUDE.md 若有项目特定组件补充，以项目级为准；本表为通用默认。设计系统约束（§十一）同理。

## 十、响应式与状态

- Vue 2数组索引和动态属性使用`this.$set`
- 弹窗关闭时清理表单值和校验状态
- 表格刷新后评估选中状态是否应清除
- `vxe-table`配置稳定、唯一的`row-id`
- 查询/重置/分页/排序调用同一数据接口，保持总数口径一致
- 无依赖请求优先并行；有依赖时注释等待原因

---

## 十一、设计系统

- 主框架：Element UI 2.15；微前端按现有Element Plus版本
- 颜色与字号：使用设计变量，禁止硬编码
- 间距：4px倍数（4/8/12/16/24/32）
- z-index：弹窗2000+、tooltip3000+
- 样式：scoped，避免全局污染
- 类名：自定义用业务前缀，不覆盖组件库内置类

---

## 十二、CSS合并

同一文件、同一作用域中的重复选择器必须合并（不同@media断点和明确级联覆盖除外）。

- `!important`高于普通声明
- 同优先级以后出现的为准
- 选择器按作用范围从大到小排列

纯CSS变更不要求业务注释，但必须检查同名class和作用域。

## 十三、组件抽取标准

> 组件库选型（el-form / vxe-table / el-table 等）见 §九。

### 必须抽取为独立 .vue 组件

| 场景 | 理由 |
|---|---|
| 弹窗/抽屉（el-dialog / el-drawer） | 主页面职责分离，弹窗逻辑独立可测试 |
| 复杂表单（>10 个字段或含嵌套/联动逻辑） | 表单逻辑复杂时独立组件更易维护 |
| 可复用业务区块（在 2 个以上页面出现） | 避免代码重复，统一维护 |
| 选项卡内的独立业务面板 | 面板逻辑独立，不污染父组件 |

### 允许保留在主页面

| 场景 | 理由 |
|---|---|
| 简单查询条件（<5 个字段，无联动） | 不值得抽组件 |
| 页面级独有逻辑且无法复用 | 抽组件增加间接层但无收益 |
| 历史代码修复，抽组件会扩大影响范围 | 最小侵入优先，参见 design-principles.md 决策矩阵 |

### 组件通信规范

```text
父 -> 子：props（数据下沉）
子 -> 父：$emit（事件上报）
弹窗数据：props 传入初始数据，$emit 返回结果
```

### 组件文件组织

```text
views/模块名/
  ├── 页面名.vue              # 主页面
  ├── components/             # 页面级组件
  │   ├── XxxDialog.vue       # 弹窗组件
  │   ├── XxxForm.vue         # 复杂表单组件
  │   └── XxxDetail.vue       # 详情面板组件
  └── mixins/                 # 页面级混入（可选）
```

## 十四、表单编辑区布局原则

- 表单项超过 4 个时，采用多列 grid 或 flex-wrap 布局
- 必填项与非必填项在同一行时，视觉权重一致（不靠缩进区分）
- 表单底部操作按钮区与表单内容区用独立容器隔离，不共享 flex 上下文

---

## 最终原则

```text
结构问题不要用样式解决。
布局问题不要用尺寸掩盖。
工程问题不要用补丁堆叠。

正确 DOM -> 正确布局模型 -> 简单 CSS -> 长期可维护代码
```

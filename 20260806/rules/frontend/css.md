# 前端布局与视觉一致性补充

> 本文件补充 `frontend/vue.md`，不替代其中既有的组件、状态、设计系统、CSS 和组件化约定。
> 修改布局时先调用 `frontend-layout`；需要重排区域或比较界面方案时先调用 `ui-design`。

## 规则职责边界

- 本文件只负责前端布局视觉一致性、字段回流、容器关系和布局验收边界。
- `frontend/vue.md` 仍是前端组件选型、Vue 状态、设计系统、CSS 通用约束和组件通信的主规则；本文件只在布局场景补充更具体的限制。
- 本文件不负责后端工程、业务假设确认、版本控制、子代理权限或最终交付格式；这些事项按对应规则文件执行。

## 设计目标

- 先确定信息层级、业务分组和用户操作路径，再选择颜色、间距和控件外观。
- 复用目标系统的主题令牌、组件尺寸、图标、文案和交互模式；未经理由不得引入新视觉语言。
- 业务系统优先保证信息密度、可扫读和高频操作效率；避免无助于任务完成的装饰和空白。
- 修改局部 UI 时，评估它与相邻区域的字号、行高、标签宽度、控件尺寸和视觉权重是否一致。

## 布局决策

- 先检查 DOM 结构、容器职责、父子关系和布局模型；确认根因后再编辑，禁止发现异常直接调 CSS。
- 内容排列错误时，优先调整结构、区域分组、grid/flex 关系或字段顺序；不得用 `margin`、固定宽高、绝对定位、`transform` 或 `!important` 压住症状。
- 页面空间不足时允许合理换行和分组；禁止 `overflow:hidden` 隐藏业务内容、压缩控件硬塞或用空元素维持错误行列。
- 不改变已有容器定位系统解决内容排列，除非现有布局模型无法表达目标结果且已说明影响范围。

## 多列表单回流

- 新增、删除或移动字段前，先列出从变更点到表单结尾的目标行列；字段变更是完整序列重排，不是孤立插入。
- 普通字段按既定列数连续自然回流；仅业务明确的长备注、说明等全宽字段独占一行。
- 新字段占用格位后，后续字段必须顺移填补空位；不得留下“新字段独占一行、后续字段仍按旧行排列”的断层。
- 新字段应完整复用相邻字段的组件结构、标签行为、必填标识、控件状态和样式模式；字段移动后保留校验、禁用、下拉、日期、清除与回显语义。

## 验收边界

- 浏览器验收覆盖变更点及其后的全部字段，检查字段顺序、每行填充、标签/控件尺寸、必填状态、无遮挡和无异常空白。
- 同时验证新增空表单和编辑回显表单；按需验证窄窗口，确认换行、滚动和按钮区域不溢出、不遮挡。
- 可预览改动检查控制台错误、失败请求、实际交互和截图；无法验证时明确阻断原因与待确认项。
- 交付说明目标布局、根因、修改层级（结构/容器/布局/CSS）、验证证据和残余风险。
